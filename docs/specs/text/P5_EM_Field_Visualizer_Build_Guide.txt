How to use this guide
This guide is a map, not a textbook. Each step gives you a goal, a task and a result to see
on screen. You write the code.
1. Something moves on screen at every step. If nothing runs, the step is too big. Split it.
2. You type every line. Ask Claude for hints, never for finished code.
3. One step at a time. Finish, see the result, commit, then move on.
4. One branch and one PR per step. main always works.
Every step has the same five lines: Goal, You'll see, Just enough, Your task and Commit.

Progress tracker
Phases 1 to 3 are done; you are in phase 4, with one field arrow on screen. Tick each box

4.2 Arrow length shows strength
Goal: the closer the arrow is to the charge, the longer it is.
You'll see: change arrowPosition from 2 to 1 , then 3 . The arrow grows and

Just enough: field strength is charge / distance² . Cheat sheet: Strength.

You'll see: the arrow looks identical, because only your code structure changed.
Just enough: JS functions return values: function fieldAt(position) { ...

EM physics cheat sheet
Only what the code needs. Read a part when a step points to it, not before.

Charge
A point charge is a tiny object with a sign: positive (+) or negative (−). In code it is a
number q and a position. Colors: red for + , blue for − .

The field
The electric field is an arrow at every point in space. It answers: which way would a tiny
positive test charge be pushed here, and how hard?
Near a + charge the arrows point away from it.
Near a − charge the arrows point toward it.

Strength
Strength drops fast with distance. Double the distance and the field is 4 times weaker.
E = \frac{k\,q}{r^2}

q is the charge, r is the distance from the charge to the point.
k is a constant. We set k = 1 , because we only want the pattern, not real units.

Direction
In code, the direction is a unit vector from the charge to the point:
\hat{r} = \frac{\text{point} - \text{charge position}}{r}

The full field vector is E · r̂. For a negative q , the sign flips the arrow automatically.

Superposition
With several charges, the field at a point is the sum of each charge's arrow, added as
vectors. No new physics is needed, only a loop and total.add(...) .
\vec{E}_{\text{total}} = \vec{E}_1 + \vec{E}_2 + \dots

Field lines
A field line is the path a tiny positive charge would follow. Where lines are dense, the field
is strong. Lines start on + charges and end on − charges.

Watch out
At r = 0 the formula divides by zero. Skip that point.
Close to a charge the strength is huge. Cap the arrow length.
Later, for the stretch goals: moving charges make magnetic fields, and Maxwell's
equations tie both together. Not needed for the MVP.

When stuck
Work down this list before asking for help. Most bugs are in the first four.
1. Open the console ( F12 , Console tab). Read the red error that mentions main.js .
Ignore errors from browser extensions like Grammarly.
2. Hard refresh with Ctrl+Shift+R . The browser may be showing an old file.
3. Check the server is running and you opened the localhost URL, not the file
directly.
4. Check the branch name in your Git Bash prompt. A stray character shows up there.
5. Print the value. Add console.log(thing) and look at what it really is. Remove it
before committing.
6. Shrink the problem. Comment out half the code and see if the bug stays.
7. Backend bugs: read the terminal where the server runs. Test the route in the browser
or with fetch in the console before blaming the UI.
8. Network tab ( F12 , Network): did the request go out, what status code came back,
what did the response say?
